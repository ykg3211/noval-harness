# 章节产物与记忆更新

沿用小说现有目录与编号；遵守其局部约定和 memory-types.md。以下是初始化结构下的默认位置：

```text
chapters/ch-NNN/
  plan.md                 续接来源、章节目标、情节方向与暂定项
  scenes/
    scene-NNN.md          场景计划、轮次与推演记录链接
    working-state.md      本章临时状态，明确非正式事实
  draft.md                正文草稿
  review.md               实质审查发现与修订结果
  changes.md              待应用变更及应用记录
  final.md                仅在实际定稿时创建
```

只讨论时无需创建所有文件。若需要保存讨论结果，记录已确定与暂定方向，不伪造正文、人物反应或定稿结果。续接草稿时先读已有内容，保留用户改动；不以新生成的整章覆盖尚未读取的文字。

## 变更提案

每条变更包含稳定 ID、目标文件、发生或生效时间、人物获知时间（适用时）、变更前后摘要、依据段落或事件、来源状态和应用状态。

正文草稿为 draft 来源；定稿后才将来源指向 final.md，来源路径相对当前文件。事件 ID 与记忆 ID 在小说内唯一，重复应用检查同一来源事件和 ID，不能重复创建。

分开列出：

- 世界事件及时间线变化。
- 人物身体、情绪、位置、资源和目标变化。
- 真实关系变化与双方主观关系变化。
- 各人物新增知识、怀疑、误解和信念修正。
- 值得长期保留的记忆及触发条件。
- 伏笔新埋设、兑现或调整，以及大纲需同步的进度。
- 阅读承诺和 payoff 的实际进展、兑现代价与后果。
- 读者新见信息、仍未解决的问题及相应正文证据，区别于人物知情范围。
- 新增叙事素材、已有梗的变奏、正式使用历史及冷却或停用建议；按 occurrence ID 和正文位置去重，定稿后更新统一索引。

短暂动作不必全部沉淀为长期记忆。根据对未来决策、信任、目标、承诺或世界理解的影响筛选；历史经历和主观解释分开写。

## 定稿更新

仅在用户要求定稿或已有对应授权时执行，不反复要求相同授权。草稿交付本身不代表定稿。

1. 审查正文与裁定结果一致，修正残留的因果冲突。
2. 保存 final.md，将本次变更对应到确切定稿来源；确认现有 final 是否是用户正在要求修订的版本，不意外替换别章。
3. 创建或更新事件，更新 timeline、人物状态、知识、关系和筛选出的记忆；来源和时间保持一致。
4. 更新人物记忆索引、小说索引及伏笔进度，大纲后续计划不改写成已发生事实。
5. 核对引用存在、时间连续、人物知情范围正确，逐项记录应用状态。

文件更新若中断，记录哪些已完成、哪些待处理，依据稳定 ID 和当前内容恢复；未全部成功前不得报告“记忆已同步”。

伏笔新埋、强化、部分回收、全部回收都要有 final.md 中可检索的证据；未完全回收的部分继续登记。更新 payoffs.md 的实际进展和 reader-state.md 的截至章；作者对读者可能猜测的判断明确标为假设，不伪装成反馈。计划窗口可调整，已有正文证据和历史状态保留。

修订已定稿章节时，先检索事件 ID 和来源，列出后续章节与人物认知依赖，再同步修订。保留信念修正的历史，不悄悄删除曾影响行为的误解。
