# 小说章节续写

默认一工程一本小说。先掌握已有剧情，再与用户共创后续；不问“续写哪本书”“前面发生了什么”。本 Skill 同时支持只讨论、写草稿和定稿，按用户当前意图推进。

## 默认编写风格

续写默认执行“语言轻松易读、主线有悬念、人物选择有代价”。具体写法与检查标准见 [references/writing-style.md](references/writing-style.md)，读取前序正文时一并读取，并用于章节计划、正文组织和交稿前自检，不只作为风格标签。

轻松易读指表达清楚、进入故事容易，不要求所有场景搞笑。吐槽反套路、规则博弈、生活流治愈、强情绪场景化和群像是可组合手法，按作品承诺及本章功能选用，不每章全部使用。用户明确的风格要求优先；已有作品保留视角、人物声线与基调，在此基础上落实准则，不擅自改写旧章或把庄重、悲伤场景强行喜剧化。

## 1. 自动读取当前剧情

读取 `revisions/index.md`（若存在）及影响本章的修订，按新的大纲与人物阶段推进。相关 partial 冲突能在授权内解决就处理，否则先讨论具体矛盾；无关待办不阻塞续写。显式失效的草稿状态或推演不能作为恢复来源。

读取工程与小说局部 `AGENTS.md`，自动定位小说。沿用根目录或 `novels/<slug>/` 的现有布局，不搬迁文件；仅当确有多个有效内容根且工程约定不能定位时才澄清路径。没有小说材料时说明缺少大纲和章节，并引导使用 novel-bootstrap，不凭空声称已读剧情。

读取 `novel.md`、`outline/overall.md`、相关分卷和故事线、伏笔，以及章节索引和前序章节。最近一章必须读正文，紧密相连的前几章也读正文；较早章节结合摘要、时间线与当前伏笔追溯原文。不能只读大纲就把计划当成已经发生的剧情。

读取小说的 `reader-promise.md`、`outline/payoffs.md`、`outline/reader-state.md` 及当前相关伏笔详情。不存在时根据已写正文暂时重建当前阅读期待与已见线索，标明推断，写作过程中按需补齐，不阻塞剧情讨论或要求用户重做初始化。

根据章号和实际内容判断进度，不按文件修改时间排序。优先识别现有未完成草稿，再识别下一章；初始化的空 `draft.md` 不算已写章节。有定稿时作为正式基线，无定稿但有连续草稿时可将其作为暂定续接上下文，明确来源与状态，不因此写入 canon。

检查与续接有关的时间线、变更应用状态和人物档案；发现档案滞后于正文时，按已发生事件重建本次工作上下文并记录待同步项，不为了读取剧情擅自定稿或覆盖记忆。仅有大纲尚无正文时，从开篇计划讨论第一章。

## 2. 立即进入剧情讨论

按 [素材入库规范](../../../harness/storycraft/asset-library.md) 读取 `story-assets/index.md`，按本章人物和处境召回相关条目与近章使用历史。没有统一索引时从已有伏笔和回报档案增量补齐，不重复发 ID。结合历史讨论本章使用、变奏、回扣或暂停的素材，避免重复消耗同一笑点或爽点。

首次实质回复用简短段落对齐当前停点、人物处境、未解矛盾，再给出具体的后续设想。不要先展示流程清单或开展偏好问卷。

结合现有因果提出一个推荐方向，必要时给出 1–2 个有差异的备选，说明各自的人物选择、冲突升级和章末变化。每轮只讨论最影响走向的 1–3 个问题，不要求用户补述文件已有信息。

此时读取共用的 [阅读期待与回报](../../../harness/storycraft/reader-engagement.md) 和 [伏笔规范](../../../harness/storycraft/foreshadowing.md)。讨论本章值得期待的变化、已有承诺如何推进、哪些长线适合埋设或回收。对久无进展、接近窗口的条目提出处理建议；不把所有作者账本展示成问卷，也不把每章写成强刺激或固定断章。

用户仅调用 Skill 或说“讨论下一章”时，默认停留在共创讨论，不提前生成完整正文或启动人物 Sub Agent。用户已经给出情节要求时围绕它深化，不重新让用户选方向。

用户说“就这样写”“你决定后续并续写”等，直接进入执行，不再增加批准步骤。只有仍需用户决定的关键创作分歧才继续询问；可用异步工具提问，否则回复提问等待下一轮。等待超时不代表选择。

## 3. 落章节计划与场景

将收敛的方向写入本章 `plan.md`：续接来源、章节目标、起始处境、参与人物、矛盾、场景节点、预期变化、章末问题及暂定项。已有草稿保留并在原章接续，不无故另起一章。

增加本章阅读体验与 payoff ID、可见进展、计划回报及后果、伏笔 ID 和本章动作（新埋、强化、部分揭示、回收、延后或不触及）、读者新增信息和继续阅读的理由。只记录与本章相关的条目；先核对实际正文证据与回收条件，不把作者设定当成读者已经看过的铺垫。

在同一计划中简记本章的风格落点：沿用的视角与声线、适用的辅助手法、要推进或阶段回答的问题，以及关键选择的取舍与后果。结合本章功能记录，余韵章可以承接既有后果，不为填写字段新增危机、惩罚或悬念；不另建重复的回报、伏笔账本。

先规划当前节点与可能后果，不把所有人物决定预先锁死。分清用户要求的创作约束和 Agent 提议的可调整路径；推演出现偏离时可调整路径，若触及用户明确约束则补足条件或讨论冲突，不默默丢弃要求。

## 4. 人物召回与独立推演

执行写作时读取 [references/character-simulation.md](references/character-simulation.md)。为每个有实质决策的人物组装仅属于他的上下文，实际调用独立 Sub Agent；普通过场由主 Agent 处理。Skill 授权的是本次小说写作中的人物推演，不包括让子 Agent 自主编辑工程。

按角色分别保存输入与反应，主 Agent 裁定结果；同一轮独立决策，观察对方行动后再进入下一轮。维护本章临时状态，供后续场景召回，但不修改正式记忆。

阅读回报和伏笔设计留在主 Agent 侧，不把“此人必须震惊/告白/失败”或未揭示答案交给人物。推演改变预期路径时保留可信选择，调整回报或铺垫条件，涉及用户明确约束时再讨论具体冲突。

推演使用独立上下文而非继承完整作者会话；具备 fork_turns 参数时指定 none。工具不可用时明确说明未实际运行 Sub Agent，改用主 Agent 分视角推演并记录降级方式，不伪造调用记录。

## 5. 正文写作与审查

将裁定结果组织成符合原作视角、语气和节奏的正文，写入 `draft.md`。不要把推演报告原样拼接进正文。文字展开若新增足以改变人物决定的事实，回到对应节点推演；语言和环境润色可直接完成。

按 [默认编写风格](references/writing-style.md) 将风格落实到场景：用具体行动、对话和细节承载信息，让悬念获得有效进展，让重要选择留下可感知的后果。风格与预期阅读效果由主 Agent 编排，不向人物 Sub Agent 下达“必须说笑话、制造反转或作出牺牲”的命令。

检查人物动机、信息边界、时间地点、伤势和物品连续性、世界规则、伏笔、章节变化和叙述风格。语言问题直接修；因果问题重新推演受影响部分，再修后续场景。记录实质问题与处理结果到 `review.md`，不生成无意义的逐条检查日志。

从正文检查回报是否有积累和后果、是否反复使用同一种冲突、伏笔细节是否真正落在页面、反转能否回读成立、读者视角是否被无故隐瞒关键信息。允许铺垫章与余韵章，但应有行动、信息、关系或人物理解的进展；不使用无依据的爽度评分。

交稿前执行风格参考中的正文自检，直接修正解释堆积、声线趋同、无进展拖悬念、无因果反转等实际问题；涉及人物决策或新事实时仍按上述推演与连续性流程处理。风格自检属于本 Skill 的内部检查，不代替 novel-review，也不触发额外批准步骤。

## 6. 交付与记忆维护

从本章讨论和正文提取有延续价值的新素材，去重后登记候选设计；实际使用先写 changes.md。定稿后记录正式使用的 occurrence ID、正文位置、变奏与后果，更新状态和统一索引，次数从有效历史推导。删除旧用法时标记失效并检查后续依赖，不能静默保留过期前情。

按 [references/chapter-records.md](references/chapter-records.md) 保存产物及变更。默认交付草稿、简短章节摘要和待应用记忆更新；用户要求定稿或已有自动定稿授权时，统一应用并检查一致性。

不要在定稿前将草稿事件写入 canon、人物正式档案或正式伏笔状态。下一章如续接未定稿章节，其变化只作为暂定上下文传递。

`changes.md` 同时提出回报进展、伏笔状态和读者信息的更新，区分计划改动与已发生记录。定稿后用实际正文来源更新三套档案，保留延后、取消或部分兑现的理由；不能提前将 planned 改为 seeded 或将回报标为已兑现。

最终回复按本轮意图给出剧情讨论，或正文文件入口、章节摘要和定稿状态。只有实际完成的推演、写作和更新才能报告为完成。

## 7. 询问是否审稿

完成实际章节正文续写并交付文件后，询问：“本章续写已完成，是否调用 novel-review 进行审稿？”可用异步工具或在最终回复末尾提出。仅讨论剧情、写作失败或没有生成有效正文时不触发。

用户确认后自动读取并执行工程 novel-review，将本次实际输出章节的确切文件路径交给它；不要再次询问是否调用，不要求用户重复指定刚写完的章节。调用前可读取本 Skill 的已交付文件记录，但不读取发布平台，平台路由由审稿 Skill 完成。

用户本轮已明确要求“写完并审稿”或先前已明确授权后续每章审稿时，正文完成后直接调用，不重复询问；用户拒绝、未回答或仅有预选时不调用，超时不当作同意。不能把默认开启的写作内部自检当成用户已同意独立审稿。
