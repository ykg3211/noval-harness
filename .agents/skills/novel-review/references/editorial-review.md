# 通用编辑审稿规范

此处是本工程的编辑方法，不是平台官方硬规则。读取对应平台说明后结合使用；不把所有作品套进同一商业节奏。

## 检查维度

| 维度 | 核心问题 | 依据 |
| --- | --- | --- |
| 续接与因果 | 上一章结果是否延续？行动能否导致结果？ | 相关正文、实际场景与世界规则 |
| 人物 | 决策是否符合当时目标、价值排序与压力？ | 人物档案、阶段历史、相关记忆 |
| 信息边界 | 谁知道什么？视角是否泄露未获知秘密？ | 知识、事件、reader-state 与正文 |
| 连续性 | 时间、地点、伤势、资源、物品是否一致？ | 正文与已确定事实 |
| 阅读体验 | 本章推进什么期待，兑现是否有积累与后果？ | reader-promise 与 payoffs |
| 伏笔与反转 | 线索是否真正出现？回收能否回读成立？ | foreshadowing 与对应正文证据 |
| 梗与笑点 | 是否符合人物，是否过密重复或破坏情绪？ | story-assets 与近章使用历史 |
| 节奏与表达 | 有无重复解释、空转对话、视角漂移、病句？ | 本章正文与既有风格 |
| 标题与结尾 | 是否贴合正文，有无虚假悬念或刻意截断？ | 本章实际变化与续接方向 |

需使用机制参考时读取工程 [阅读回报](../../../../harness/storycraft/reader-engagement.md)、[伏笔](../../../../harness/storycraft/foreshadowing.md) 和 [素材库](../../../../harness/storycraft/asset-library.md)；它们只提供分析工具。

允许铺垫、日常、失利、悲剧与余韵。不是每章都要高潮、反转和新坑；必须具体解释为什么某处未发挥本章作用，不能只写“爽点不足”。多种合理审美之间的取舍标为建议。

## 问题分级

- P1：明确的重大因果或连续性错误，破坏关键决策或使章节无法成立；有确切依据的严重平台要求问题也可列此级。
- P2：显著影响阅读理解或期待推进，修复范围相对局部。
- P3：文字与表现优化，不影响基本成立。

证据不充分的疑问单列“需核实”，不因不确定就提升优先级。相同原因合并，优先报告最影响作品的问题。

## 问题格式

`问题 ID / 优先级 / 依据类别及证据级别 / 适用范围 / 文件与位置 / 正文证据 / 影响 / 修改方向 / 规则或关联档案来源 / 是否需人工补充或决策`。

正文证据应短且足够定位；行号必须来自实际文件。建议给局部调整方向，不擅自改成另一种人设或另一条主线。平台判断附具体官方来源，编辑建议附具体情节依据。

## 报告结构

```markdown
---
id: review-001
kind: chapter-review
platform: qimao
target: ../draft.md
target_sha256: 实际工具计算值
---

# 章节审稿

## 审阅范围与依据
章节或投稿范围、目标通道（适用时）、全部正文及辅助材料的版本与 hash、平台说明版本与核实日期；已知 AI 用途；无法核实的范围。

## 结论
分开记录材料完整性（适用时）、故事质量、内容发布与权利疑点、创作方式与通道适配。不适用项写不适用；未审正文写未评估。

## 问题与修改建议
按影响排序，逐项包含正文定位与依据类别。

## 需核实项
材料不足或外部规则无法确认的事项。

## 建议处理顺序
具体修稿路径；若无问题，不制造修稿任务。
```

审稿报告不进入 canon 或人物记忆。写作内部自检和独立审稿分别记录，不冒称已由平台编辑审核。
