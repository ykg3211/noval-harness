# 影响分析与同步

## 变更映射

| 改动对象 | 直接修改 | 关联检查 |
| --- | --- | --- |
| 主线目标、对手或结局 | outline/overall、相关 arcs、volumes、design | 章节因果、角色目标、主题与阅读承诺 |
| 章节顺序或转折 | 大纲、相关章节 plan | 故事时间、人物位置、获知顺序、伏笔先后 |
| 性格补充、修正 | profile、必要的 personality-history | goals、关系、已有决策、专属梗的适用性 |
| 成长方向 | 成长线、未来章节计划 | 转变的触发和代价，当前 profile 不提前变更 |
| 背景或旧事件 | 背景设计，授权范围内的正文、canon/events、timeline | 目击者、传闻、知识、记忆和后续决策 |
| 秘密或身份真相 | 秘密设计或 canon/secrets（已确定基线） | 知情范围、旧线索、误导的合理性、揭示条件 |
| 回报或伏笔取消、延后 | payoffs、foreshadowing 与详情 | 已向读者建立的期待如何回应，旧证据保留 |
| 梗的修改或停用 | story-assets 原条目与统一索引 | 历次用法、角色依据、后文回扣与冷却状态 |

只修改有实际影响的文件，不为流程完整而触碰每个档案。内容路径沿用现有结构。

## 依赖检索

先用 rg 搜稳定 ID、角色名、原设定关键词和来源路径，再读具体上下文。评估四层：作者计划、世界事实、人物认知、读者已见信息。全文搜索是定位手段，语义影响还需检查相关故事线，不把零命中当作无影响。

读取共用 [阅读回报](../../../../harness/storycraft/reader-engagement.md)、[伏笔](../../../../harness/storycraft/foreshadowing.md) 和 [素材库](../../../../harness/storycraft/asset-library.md) 中与本次改动相关的规范。只改当前涉及条目，不重新研究市场。

## 人物性格的时间维度

profile 描述当前适用的行为依据，若有阶段差异注明 as_of 与生效条件。`characters/<id>/personality-history.md` 按需记录阶段、特征、触发来源、适用故事时间及性质（作者修订或故事内成长）。

例如补充“冷淡，但会认真履行对弱者的承诺”，应写出行为例外和价值排序，不把过往所有帮助行为改成冷酷。若用户要求“从开篇就不信任任何人”，则需检查旧章合作、托付和秘密共享能否成立，并提出具体修法。

作者改设定不是人物获知的新消息，不创建“人物意识到作者改了性格”的记忆。故事内转变只有正文发生后才更新当前状态；回写过去场景时从阶段历史恢复当时特征。

追溯修改背景事实时，人可能亲历、被告知或误解，逐人决定知识与记忆是否变化；不要把作者真相批量复制到所有人。保留仍有意义的误解历史。

## 修订记录

按需创建小说 `revisions/`，不要求事先运行初始化。索引列修订 ID、摘要、范围、状态、记录链接及未决影响。

单次记录建议结构：

```markdown
---
id: rev-001
kind: editorial-revision
status: proposed
---

# 修订主题

## 用户要求与采用方案
明确要求、Agent 建议、暂定项分别记录。

## 生效范围
补充、前向发展或追溯修改；时间与章节边界；正文是否在范围内。

## 修改前后
原档案关键片段及来源、新内容、修改理由；必要时保留较大范围的原文快照。

## 影响与应用记录
| 目标文件 / 对象 ID | 原因与依赖 | 处理内容 | 状态 | 更新后依据 |
| --- | --- | --- | --- | --- |

## 待处理与验证
未解决冲突、下一步、已完成检查及局限。
```

只记录可审阅的编辑说明，不记录隐藏推理。更新失败时保留记录和已完成变更，不覆盖为“成功”；恢复时以实际文件核对记录。用户要求撤销时按原片段与当前内容反向修订，保留撤销记录，不用 git reset 清掉无关工作。

## 与续写衔接

续写应读取 revisions/index 及相关修订，采用新设计和人物阶段；遇到 partial 中影响本章的冲突，先读新旧正文和记录，能在授权范围内解决则完成，否则讨论具体矛盾，不能默默使用互相冲突的设定。与本章无关的待办不阻塞创作。

修订正文后重新核对变化提案、定稿来源和已应用状态，标记过期的草稿、临时状态与推演引用，以免下次续写恢复旧状态。素材正式历史保留 superseded 记录，次数仅计有效版本。
