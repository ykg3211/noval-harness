# 小说框架初始化

产出支撑后续“主 Agent 召回人物 → 人物 Sub Agent 推演 → 正文定稿 → 记忆更新”的小说档案。使用用户的语言交流和写作。此 Skill 负责共创与初始化，不默认开始写第一章。

## 1. 了解已有材料

读取工程 `AGENTS.md`，检查工程根目录、`novels/` 与用户指定的材料。默认一个工程只有一本小说，自动定位已有大纲与人物档案，不增加选书步骤。已有回答直接沿用，不让用户重复填写。

若小说已存在，阅读其索引与设计，补充缺失文件和内容；不要运行初始化脚本覆盖它。新小说的 slug 可根据标题自动生成，不必专门询问。仅在用户明确要求另建一本时使用独立目录。

若用户实质要求修改已有主线或人物设定，转用工程 novel-revise；读取已有 revisions/index.md 及相关修订，避免初始化补档时恢复失效设计。

## 2. 分轮探索

按 [references/discovery.md](references/discovery.md) 开展对话。先问最影响设计的少量问题，等待回答，再提出有差异的故事方向并解释取舍。每轮通常只问 1–3 个问题；不要一次交付整份问卷。

有异步提问工具时可使用；否则直接在回复中提问并等待下一轮。不要把等待超时视为回答，也不要在等待时替用户作出关键创作选择。可继续整理已有信息。

每轮维护“已确定 / 建议方案 / 待定”三类信息，解释人物欲望、核心矛盾与结构如何相互支撑。用户提出方向后，要给具体设想，不能只持续提问。

先围绕故事承诺、主角、核心冲突形成概念，再深化世界规则、人物关系和结构。允许单线、群像、双线、单元剧或其他形式，不强制三幕式，不预设类型、篇幅、结局或恋爱线。

探索阅读体验时读取 [阅读期待与回报](../../../harness/storycraft/reader-engagement.md)，具体讨论这本书让读者期待什么、怎样感知进展、凭什么兑现。主辅回报可以是成长、尊严、智谋、公正、关系、探索、建设、幽默或救赎，不默认套用受辱后打脸。结合类型选用，不把所有机制变成新增问卷。

用户说“你决定”“先初始化一版”时，采用与已知偏好一致的建议，记录为暂定设计并继续；不要反复索取确认。信息不足且用户希望继续探索时，继续对话，不提前生成任意小说。

## 3. 收敛设计

给出可审阅的框架：一句话故事、读者体验、主角欲望与弱点、主要阻力、世界边界、关键人物与关系、故事线、关键转折、开篇入口、风格与篇幅，以及未决问题。

读取 [伏笔、彩蛋与读者信息](../../../harness/storycraft/foreshadowing.md)，把全书关键回报倒推到早期前置条件。给出短线进展、阶段回报与核心兑现的联系，以及关键长线伏笔的自然埋设、变奏强化、部分揭示和回收条件。彩蛋与必要线索分开；结局未定时保留兼容解释，不强行锁定答案。

用户已经要求按当前方向初始化时直接执行。仍有影响整体方向的分歧时，询问具体分歧，不追加泛泛的批准流程。无需强求结局和全部章节都确定，开放项显式保留。

## 4. 初始化 Markdown 档案

读取 [素材入库规范](../../../harness/storycraft/asset-library.md)，将讨论中决定保留的长期伏笔、彩蛋、专属梗、笑点和爽点登记到 `story-assets/index.md`。引用原伏笔和回报档案，专属梗在 `story-assets/motifs/` 独立建条目，写明人物依据、触发条件、变奏和停用条件。无正文时只记设计与计划，不虚构使用历史；不为了填库存编造素材。

读取 [references/structure.md](references/structure.md)，遵守目录职责、元数据和事实边界。

新小说可使用自带脚本创建骨架（路径替换为该 Skill 的真实位置）：

```bash
python3 <skill-dir>/scripts/init_novel.py \
  --root <project-root> --slug <novel-slug> --title '小说标题' \
  --character 'char-lin=林舟' --character 'char-zhou=周衡'
```

`--character` 可重复，也可省略。slug 和 ID 使用小写英文、数字及连字符；中文名称放标题和正文。脚本拒绝已存在的目标目录，只创建骨架，不生成故事内容。不要把骨架当作完成结果。

用本轮设计填充生成的文档；新增已讨论的故事线、世界实体、人物关系、初始秘密与记忆文件。标记已确定、暂定和待定，保留关键设计取舍及理由。

- 初始人物写明目标、价值排序、弱点、底线、压力下的反应及成长方向，避免只有性格标签。
- 世界规则包含约束或代价；关系包含欲望、冲突、依赖和双方认知差异。
- 背景经历可成为开篇前的初始事实，但必须有设计来源；未来大纲事件不得写成已发生记忆。
- 只为有具体内容的关系、记忆和实体生成条目。没有已确认记忆时保留空索引，不编造经历凑数。
- `plan.md` 写开篇目标和场景计划；正文保持未撰写。可概述开篇情境，不自动写章节正文。
- 用户选择与 Agent 暂定设计写入 `design.md`，不得将建议伪装为用户明确决定。
- 小说持久内容使用 Markdown，可用 YAML frontmatter，不以独立 JSON/YAML 文件替代档案。
- 填充 `reader-promise.md` 与 `outline/payoffs.md`，把主要阅读承诺和阶段兑现具体关联到人物目标、阻力、选择、积累与后果，不只写“燃”“爽”。
- 填充 `outline/foreshadowing.md`，复杂长线另建详情；登记类型、计划窗口、关联回报和知情范围。无正文时实际状态为 planned，不登记为已埋设。
- 建立 `outline/reader-state.md`；无正文时写明尚无读者已见信息，不能从作者大纲推断读者知道什么。

## 5. 检查并交付

检查索引链接及 ID 引用有效、人物视角未泄露秘密、故事时间没有倒置、正式事实未混入未来计划。核对设计中的人物和故事线已落到对应文件；读取产出内容，不能仅检查目录存在。

核对核心回报是否有前置积累、长期揭示是否有早期可呈现的依据、开篇是否能示范主要体验。不能为追求爽点让人物违背动机，也不能以长期挖坑替代阶段回应。相关研究及适用边界见 [研究依据](../../../harness/storycraft/research.md)，不将创作假设宣传为市场保证。

确认核心文件已有具体设计；未决问题集中记录，不得仍只是空模板。工具失败时修复后再报告完成，无法修复则说明已完成部分与失败位置。

最后给出小说目录、框架摘要、关键未决问题及下一步入口。说明初始化了哪些人物和记忆；不暗示已经执行人物 Sub Agent 推演。推演协议见结构参考，完整章节执行器属于后续工作。
