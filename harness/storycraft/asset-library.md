# 小说叙事素材入库与更新

为长期伏笔、彩蛋、专属梗、笑点和爽点建立可检索档案。全部使用 Markdown，由主 Agent 按 Skill 执行读写，不是后台自动同步服务。

## 统一入口，保留单一来源

```text
story-assets/index.md         全部长期素材的检索入口
story-assets/motifs/gag-001.md 专属梗、笑点详情
story-assets/motifs/motif-001.md 标志性动作、口头禅、意象详情
outline/foreshadowing.md       原伏笔、彩蛋与回扣索引
outline/foreshadowing/         复杂条目详情
outline/payoffs.md            原爽点与其他阅读回报条目
```

统一入口保存 ID、类型、摘要、关联人物、触发标签、状态摘要和详情链接。伏笔沿用 fs ID 与原档案，爽点沿用 payoff ID，不复制第二份正文或另发 ID。简单条目可用文件内标题锚点定位，复杂后再提取独立文件并更新链接。

索引是可重建摘要，以条目与正文证据为准。已有小说增量补入口，不搬迁或覆盖原文。

## 入库条件

框架中决定保留的长线设计、用户指定的专属梗、草稿中新出现且有延续价值的细节，都可以入库为候选设计。已有正文里的重复元素可以追溯登记，但不能伪称早已规划。

一次性修辞、普通动作和无延续价值的小笑话不强制入库。严肃小说不必有笑点库存。

## 专属梗条目模板

```markdown
---
id: gag-001
kind: narrative-asset
type: running-gag
design_status: provisional
actual_status: planned
characters: []
tags: []
related_assets: []
---

# 梗的名称

## 机制与人物依据
反差、误会或期待怎样形成，为什么适合这些人物。

## 触发与边界
适用情境、谁知道前情、不适用条件。

## 变奏与升级
首次建立、改变语境、反转或情感回扣等可能路径。

## 节奏与停用条件
如何避免重复；何时暂停、转义或结束。

## 计划使用
候选场景与目的，不算已经发生。

## 正式使用历史
| occurrence ID | 定稿章节 / 正文定位 | 具体变奏 | 角色知情变化 | 后果 | 有效状态 |
| --- | --- | --- | --- | --- | --- |

## 修订记录
变更原因及受影响的正文与关联条目。
```

related_assets 引用已有 fs、payoff 或 motif ID，关联同一个细节的笑点、伏笔与情感回扣。没有关联用空列表，不造悬空 ID。

梗的实际状态为 planned、active、cooling、retired；伏笔沿用自己的埋设回收状态。使用次数、首次与最近使用章从有效的正式历史推导，不从计划或模型印象估计。不虚构读者反馈。

## 章前召回

主 Agent 按在场人物、处境、地点、物品和情绪目标检索索引，再读相关详情与近章使用历史，选择使用、变奏、回扣、延后或暂停。近章重复、人物成长使机制失效或当前情绪不适合时，改变或停用，不机械套用库存。

人物 Sub Agent 只接收角色亲历的前情和可感知触发，不接收作者的包袱答案、未来回收计划，也不被命令必须表演笑点。

## 章后与定稿更新

1. 从讨论和正文提取有长期价值的条目，按机制、人物和来源检索去重；已有条目增加变奏或关联。
2. 草稿阶段可登记候选设计与计划，实际出现、回扣或冷却建议写入 changes.md，来源标 draft；不提前更新正式历史、次数和实际状态。
3. 定稿后依据 final.md 添加稳定 occurrence ID、可检索正文定位、变奏、后果和有效状态，并应用相关伏笔、回报和必要的人物记忆更新。出场不代表所有人物都理解前情。
4. 更新统一索引；以 occurrence ID 及条目 ID 加正文位置去重，避免重复计数。
5. 中断时在 changes.md 记录逐项应用状态，恢复后继续；条目、索引和关联档案一致才报告同步完成。

素材使用不自动形成角色长期记忆，只有影响未来选择、关系或认知的经历才沉淀到人物档案。

## 修订与取消

删改正式使用时，原历史行标 superseded 并记录新来源；有效次数仅计现行版本。检查依赖旧铺垫的后续变奏、伏笔和关系变化，不能让后文引用已删除前情。

计划可取消并记录理由。已向读者建立的核心问题需在正文交代，不能只在素材库标 retired。保留修订来源。
